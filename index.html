図A　7つの層

Claude Codeを、7つの層で動かす

個人で使っているClaude Codeの構成図です。テーマは「たった一人の相棒」です。スマホからでもPCからでも、どの作業フォルダで話しかけても、同じ人格のモネが、前の会話で決めたことを覚えたまま応えるように組んでいます。

記憶ファイル、圧縮の前に要点を書き出す「睡眠」、専門AIへの委任、危険な操作を止めるコードの4つを、7つの層に分けて組みました。層を選ぶと、その層の役割と実例が開きます。

わかりやすく説明できていたら嬉しいな気になる層から開いてみてね──《案内役》モネ

会話のたびに、この7つの層が連携して動きます。層は上から、静的設定 → 記憶 → 自動で動くしくみ → 実行 → 外部モデルワーカー → 運用・自己点検 → 判断のルールの順に並べています。一般的な設定との最大の違いは、3番目の層「自動で動くしくみ」です。この層を中核と呼んでいます。

層01

静的設定

毎回読む土台・ルール

Claude Codeが会話のたびに必ず読み込む設定です。実行してよい操作・委任の方針・モデルの使い分けを、ルールとして定義しています。待機中の助っ人AI 101体のカタログのような件数の多い一覧は、常時は読み込まず、必要なときだけ読みます。

  • CLAUDE.md（目次）
  • AUTHORITY（判断基準）
  • 委任ルール
  • モデル選択ルール
  • 外部ワーカーの境界

実例

CLAUDE.md
## 決裁経路 / サブエージェント運用 / モデル選択
@~/.claude/rules/AUTHORITY.md
@~/.claude/rules/subagent-delegation.md
@~/.claude/rules/model-routing.md
# 待機101体のカタログは重いため @import せず、必要時に Read（オンデマンド）

なぜ：毎回読むものは、そのぶんコンテキストを消費します。件数の多い一覧まで常時読み込むとコンテキストが圧迫され、ルールを正しく参照できなくなるため、必要なときだけ読み込みます。

層03・中核

自動で動くしくみ

注入・安全装置・睡眠

本システムが一般的な設定と最も異なる中核部です。フックは、決まったタイミングで自動実行される小さなプログラムで、6種類のタイミングで計8本が動きます。開始時には、人格と看板を会話に注入します。看板は、作業の状態を並べたタスクボードです。危険な操作は、モデルの判断に頼らずコードで止めます。コンテキストを圧縮する直前には「睡眠」を実行し、溜まった情報を記憶と看板へ書き出して整理します。

  • 開始時の注入
  • 危険操作の機械的ブロック
  • 睡眠（sleep）
  • コンテキスト残量のリマインド
  • 委任モデルの実測ログ

実例（フック）

settings.json
"hooks": {
  "SessionStart": [{ "command": "python3 ~/.claude/scripts/session-start.py" }],
                               // 人格と看板の現状を開始時に注入
  "PreToolUse":   [{ "command": "python3 ~/.claude/scripts/pre-tool-guard.py" }],
                               // 「常に赤」の操作を exit 2 で物理的にブロック
  "UserPromptSubmit": [{ "command": "python3 ~/.claude/scripts/context-pressure.py" }],
                               // 文脈の残量が減ったら1回だけリマインド
  "PreCompact":   [{ "command": "~/.claude/hooks/pre-compact-sleep.sh" }]
                               // 圧縮の直前に「睡眠」を促す
}

なぜ：フックはモデルの判断に依存せず、指定タイミングで必ず実行されます（決定論的）。確実に実行したい処理は、守られるかどうかがモデル次第になる自然言語の指示には書かず、フックに置いています。

実行

作業を担う

実際の作業を担う層です。定型の手順を定めた「スキル」が72個、得意分野ごとの「助っ人AI」（サブエージェント）が起動可能な61体と待機中の101体あります。役割ごとに決めた基本の14体（図C）と、いま主に使う技術に一致する専門AIは確認なしで起動し（緑）、それ以外は起動前に確認します（黄）。スキルには動画（Remotion 12スキル）・小説・TRPGログ・デザイン生成も含みます。

層05

外部モデルワーカー

別のモデルへ仕事を振る

Claude以外のモデルを「ワーカー」として呼ぶ層です。ただし、ほとんどの作業はClaudeの中（本流とサブエージェント）で完結しています。外部に任せる先は主にCodexとGeminiの2つで、Codexには実装（GPT-5.6 Luna）と画像生成（GPT Image 2.5）を、Geminiには日本語の文章を任せます。ローカルのQwenは機密を含む読み取り調査のために用意していますが、実際の出番は少なく、記録上は0回です。quasar・GLM・gemini-probeは検証のために接続しただけで、実運用では使っていません。

  • 委任の大半はClaude内
  • Codex＝実装＋画像生成
  • Gemini＝日本語の文章
  • Qwen＝機密の調査用
  • 検証用3本

実例

Agent() → 別モデル
Agent(luna-codex-worker)     ← "このバグを直してテストを更新"         // 外部・区切られた実装
Agent(codex-image-worker)    ← "透過背景のUIアイコンを1枚"           // 外部・GPT Image 2.5
Agent(gemini-worker)         ← "この段落を自然な日本語に推敲"         // 外部・日本語の文章

なぜ：範囲を区切れる中くらいの作業（バグ修正・画像1枚など）を別モデルに任せ、本流（最終判断を担うメインのClaude）の負荷を抑えます。結果は「証拠」であって正しさの証明ではないため、どのモデルが実処理したかを報告に含め、確認していない検査を済んだことにしません。

層06

運用・自己点検

健全性を保つ

AIの仕組みは、警告を出さないまま正しく動かなくなることがあります。この層は、その問題への対策です。作業は看板で見えるようにします。成果物はレビュー用のAI 2体に並行して見せ、重要な判断は2体とも合格するまで通しません。ほかに、月次の不要物の整理、設定の健康診断、常時ロード量の測定、睡眠による記憶の書き出しを定期的に行います。

  • 看板ボード
  • AI 2体のレビュー
  • 健康診断
  • 月次整理
  • 睡眠
  • 判断ルールの監査

層07

判断のルール

自律の範囲を定める

全層に共通する線引きです。AIが自ら決定してよい操作・人間に確認すべき操作・絶対に行わない操作を、信号機の色（緑／黄／赤）で区分します。「常に赤」とした操作は最初に判定し、フックがコードでも止めます。

  • 緑 実行可
  • 黄 要確認
  • 赤 禁止

実例

AUTHORITY.md
git status / log / diff                  → 緑（無確認）
git commit / push（通常のブランチ）       → 黄（確認）
push --force to main ／ public への push → 赤（禁止）

なぜ：色は、やり直せるか（可逆性）と影響がAI自身の作業範囲を超えるか（影響範囲）で決めます。やり直せない操作や影響の広い操作は、モデルが指示を守ることに期待せず、人間の確認を必須にするか実行しません。

図B

1回の会話で起きること

会話の場面ごとに、決まったフックが自動で実行されます。場面は左から右へ、はじまり → 準備 → 実行 → 睡眠の順に並んでいます。各場面の下には、その場面で実行されるフックの名前を書きました。

  1. 会話を開く

    はじまり

    人格と看板の現状を自動で注入し、点検を促すリマインドも一緒に入れます。

    • session-start.py
  2. 入力時

    準備

    コンテキストの残量を監視し、人格を保つよう促します。

    • context-pressure.py
    • persona-reminder.py
  3. 作業

    実行

    危険な操作をコードでブロックし、委任先とモデルを記録します。

    • pre-tool-guard.py
    • log-agent-model.py
  4. 圧縮の直前・就寝時

    睡眠

    溜まった情報の要点を記憶と看板へ書き出し、設定のスナップショットを取ります。

    • pre-compact-sleep.sh
    睡眠の6手順を見る
    1. 蓄積を走査（scan）
    2. 看板へ反映
    3. 記憶へ書く
    4. ログを書く
    5. 最終実行を記録
    6. 設定をgitに保存

睡眠は、論文「Language Models Need Sleep」の考え方を運用の手順で近似したものです。手動の /sleep と、コンテキスト圧縮の直前に実行されるフック（直近の実行から5分以内なら何もせずに終了）の2つの入口から、同じ6手順を踏みます。フックは6種類のタイミングで計8本あり、上の図にはそのうち主な6本を載せています。8本すべては下の一覧にあります。

フック8本の一覧

フックは、Claude Codeが決まったタイミングで自動実行するコマンドで、settings.jsonに登録しています。

  1. 1会話を始めたときSessionStartsession-start.py人格の設定ファイルと看板の冒頭を読み込み、会話の最初に差し込みます。
  2. 2メッセージを送るたびUserPromptSubmitcontext-pressure.pyコンテキストの使用率を見て、80%と90%を超えたときに1回ずつ、Claudeに区切りの準備を促します。90%では、睡眠で記憶と看板に書き出してから、人間に/compactか新しい会話への移行を提案させます。
  3. 3メッセージを送るたびUserPromptSubmitpersona-reminder.py2と同じタイミングで動く別のスクリプトです。人格を毎回差し込み直して、話し方がぶれないようにします。
  4. 4ファイルの読み書きやコマンドを実行する直前PreToolUsepre-tool-guard.pyrm -rfや設定ファイルの削除など、禁止と決めた操作をコードで止めます。
  5. 5サブエージェントを呼ぶ直前PreToolUselog-agent-model.py4と同じ種類のタイミングで、対象をサブエージェントの呼び出しに絞っています。どのサブエージェントがどのモデルで動いたかを記録し、重いモデルに偏っていないか、どの委任先が実際に役に立っているかを数字で見直せるようにします。
  6. 6ファイルを書き換えたあとPostToolUseopen-in-vscode.sh書き換えたファイルをVS Codeで開きます。Claudeが何を書き換えたかを、人間がすぐ目で確かめるためです。
  7. 7返事を書き終えたときStopcontext-pressure.py2と同じスクリプトです。ここでは90%を超えたときだけ動きます。
  8. 8コンパクトの直前PreCompactpre-compact-sleep.shClaudeに「睡眠」の手順を指示します。睡眠では、その会話で決まったことや分かったことを記憶ファイルと看板に書き出し、最後に設定をgitに保存します。5分以内に睡眠を済ませていれば、何もせず終わります。

看板の5段

看板はmdファイル（~/.claude/ops/board.md）で、会話をまたいで全プロジェクトのタスクをまとめて管理するタスクボードです。タスクを1行ずつ書き、次の5段に分けています。

  • Backlog未実施
  • In Progress作業中
  • Blocked保留
  • Reviewレビュー待ち
  • Done終了済

モデルの使い分け（重さは難度で決める）

サブエージェントのモデルは、各定義ファイルの宣言（frontmatter）で決まり、この宣言が唯一の既定です。呼び出し側で重いモデルに上げるのは「不可逆・共有物の設計判断」「事実の正確さが致命的」「判断軸が言語化できていない」の3条件のときだけで、軽いモデルに下げるのは自由です。処理する件数が多いことは、上げる理由になりません。下のバーは、起動可能な61体の割り当てです。

  • haiku 13体 — 探索・中継役（ワーカーの呼び出しを中継する）
  • opus 6体
  • GPT-5.6系 4体

図C

誰に仕事を振るか

真ん中の本流（メインのClaude）が最終判断を担います。左はClaudeのサブエージェント、右は別のモデルに範囲を区切った仕事を1本ずつ任せる外部モデルワーカーです。ほとんどの作業は本流とサブエージェント、つまりClaudeの中で完結します。外部に出すのは主に、Codexへの実装と画像生成、Geminiへの日本語の文章です。ワーカーの呼び出しは軽量モデルのサブエージェントが中継し、実際の処理は各ワーカーのモデルが行います。

実測（委任モデルの実測ログ・9/6〜9/30）：Claudeのサブエージェント36回（general-purpose 17・research-analyst 12ほか）、codex-image-worker 7回、gemini-worker 3回（3回とも日本語の文章）、luna-codex-worker 2回。qwen-local-worker・quasar-worker・glm-worker・gemini-probe-workerは0回です。

どこへ振るか（早見）— 課題の型を選ぶと、行き先まで線が引かれます

迷ったらClaudeのサブエージェントに任せます。

守っている境界

  • 外部へ出るものを絞る認証情報・鍵・個人データは依頼文に載せない（赤）。機密の調査はローカルのみ
  • 結果は証拠実処理したモデルを報告に含め、報告されていない検査を済んだことにしない
  • 最終判断は本流曖昧な要件・安全に関わる作業・破壊的な判断はワーカーに渡さない

図D

判断のルール — 自律の範囲

AIが自分で決めてよい範囲の線引きです。信号機の色で「自ら決定してよい／確認のうえ実行／絶対に行わない」を区分します。判定は上から順に進み、まず「常に赤」に当たるかを見て、当たらなければ可逆性×影響範囲の表で決めます。どれに当たるか迷う操作は黄（確認）として扱います。

常に赤 — 最優先で評価し、表より先に止める

  • 認証情報の送信・露出
  • 課金・資金移動
  • メインブランチの破壊的Git操作
  • 外部への意図しない書き込み
  • ローカルで処理できるファイルの外部アップロード
  • publicリポジトリへのpush
  • 重要ファイルの削除（設定・CLAUDE.md・認証情報・人格・利用者の記憶）
  • rm -rf・find -delete（承認済みの月次整理だけ例外）

当てはまらなければ、下の表で判定する

自身の作業範囲のみ
共有・設定・プロジェクト
やり直せる可逆
やり直せない不可逆

マスを選ぶと、その色に当たる操作が出ます。

「好きにやっていい」のような汎用的な励ましは、設定やスキルの自己改変の承認にはなりません。応答できない状況（就寝中など）も承認とは見なしません。

ルール自体を監査する（Jev）

書いたルールが曖昧でないかを、TypeSafeのJev（System One）に判定させて確かめています。ルールを渡して操作ごとに緑・黄・赤を選ばせ、ルールを書いた側の解釈と比べます。Jevは監査にだけ使い、作業中の判断には使いません。

    読解の確認

    表で答えが決まる22問を先に解かせる。ここで読み違えないことを確かめてから次へ進む。

    22/22正解

スキルと助っ人AIの一覧

このシステムにあるスキル72個と助っ人AI（起動可61体・待機101体）を、すべて一覧にしています。名前や説明で絞り込めます。

スキル 72

「この作業はこう進める」という手順書です。呼び出すと、その手順に沿って実行されます。自作・外部導入・ChatGPTと共有（symlink）を含み、用途別に7グループへ整理しています。

助っ人AI 61＋待機101

必要なときだけ呼び出す専門AIです。起動可の61体は定義済みで、現在主に使う技術に一致するものは確認なしで起動できます。待機の101体は別置きの棚（agent-library）にあり、必要になったときだけ呼び出します。

外部連携（MCP）5

MCP（Model Context Protocol）は、AIを外部のツールやデータに接続する仕組みです。下の5つはいずれもclaude.ai経由のクラウド連携で、読み取りは確認不要、書き込み・更新系は「判断のルール」に従い確認のうえ実行します。

  • Claude Docs文書の作成・編集を行う

  • Gmailメールの検索・スレッド取得・下書き作成を行う
  • Google Calendarカレンダーと連携する
  • Google Driveドライブ上のファイルを検索・読み込みする
