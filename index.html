Custom Agent System

本構成は、単なる設定ファイルの集合ではありません。記憶を保持し、眠って整理し、専門エージェントや外部モデルに仕事を振り分け、自らを点検する「7層のAIエージェント組織」として動作します。各タブから、その全体像をご覧いただけます。

// Overview

What Is This?これは何か — ひとことで

会話のたびに、この7つの層が連携して動作します。上の層ほど土台・記憶を、下の層ほど実行・判断を担います。中でも3番目の層が中核で、一般的な設定と最も異なる部分です。

覚えている

過去の会話の事実や決定事項をファイルに残し、次回も参照します。

眠って整理する

会話の終わりや圧縮の直前に、蓄積した情報を記憶と看板へ蒸留します。

専門家と外部モデルに振る

得意分野ごとの専門AIに加え、速さ・場所（ローカル／外部）の異なるモデルへ仕事を振り分けます。

自らを点検する

設定の不整合を定期的に検査し、危険な操作はコードで止め、人間の確認が必要な操作では停止して問い合わせます。

// The Seven Layers

Seven Layers7つの層 — それぞれの役割

上から下へ、土台 → 記憶 → 自動制御 → 実行 → 外部モデル → 運用 → 判断の順に積み上がっています。

LAYER 01

静的設定

毎回読む土台・ルール

会話のたびに必ず読み込む土台です。実行可能な操作・委任の方針・モデルの使い分けをルールとして定義します。重い一覧は常時読み込まず、必要なときだけ読む方式にして文脈の圧迫を避けています。

CLAUDE.md（目次）AUTHORITY（判断基準）委任ルールモデル選択ルール外部ワーカーの境界
LAYER 02

記憶

会話をまたいで覚える

会話が終了しても保持される記憶です。「利用者の好み」「作業方針」「進行中の案件」「外部リソース」の4種類に分け、コードからは読み取れない事実と判断の理由を100ファイル（作業方針46・外部リソース37・案件14・利用者3）と索引で蓄積します。

索引（MEMORY.md）利用者情報作業方針案件メモ外部リソース
中核
LAYER 03

自動で動くしくみ

注入・安全装置・睡眠

本システムが一般的な設定と最も異なる中核部です。6種類のタイミングで計8本のフック（自動実行される小さなプログラム）が動きます。開始時に人格と看板を注入し、危険な操作は判断に頼らずコードで止め、コンテキスト圧縮の直前には「睡眠」で記憶を整理します。

開始時の注入危険操作の機械的ブロック睡眠（sleep）文脈の残量リマインド委任モデルの実測ログ
LAYER 04

実行

作業を担う

実際の作業を担う層です。定型手順をこなす「スキル」が72個、得意分野ごとの「助っ人AI」が起動可能62体（待機101体）。委任先は「基本の14体は常に緑、現在主に使う技術に一致する専門AIも緑、それ以外は黄」で決まります。動画（Remotion 12スキル）・小説・TRPGログ・デザイン生成のスキルも含みます。

スキル 72助っ人AI 62待機 101役割の4階層
新層
LAYER 05

外部モデルワーカー

別のモデルへ仕事を振る

Claude 以外のモデルを「ワーカー」として呼ぶ層です。Codex は実装（GPT-5.6 Luna）と画像生成（GPT Image 2.5）の2本柱、読み取り調査はローカルの Qwen3.8 27B、文章生成と急ぎの調査は Gemini、段階的な分析は GLM など。ローカルか外部か、速いか遅いかで使い分け、機密はローカルだけに限ります。

ワーカー 7ローカル 1外部 6Codex＝実装＋画像生成停止中 1本を除く
LAYER 06

運用・自己点検

健全性を保つ

「AIの仕組みは警告なく静かに壊れる」という課題への対策層です。作業を看板で可視化し、成果物は2名体制でレビュー（重要な判断は全員一致まで）、月次で不要物を整理し、設定の健康診断・常時ロード量の測定・睡眠による記憶の蒸留を回します。

看板ボード2名レビュー健康診断月次整理睡眠決裁の監査
LAYER 07

判断のルール

自律の範囲を定める

全層を貫く責任の線引きです。AIが自ら決定してよい操作・人間に確認すべき操作・絶対に行わない操作を、信号機の色（緑／黄／赤）で区分します。赤は「常に最優先で評価」され、フックがコードでも止めます。詳細は「判断のルール」タブをご覧ください。

緑 実行可黄 要確認赤 禁止

// How It Works

How a Chat Flows1回の会話で起きること

会話の各場面で、自動スイッチ（フック）が順に働きます。

会話の流れ

左から右へ。各場面で自動スイッチが発火します。

眠って整理する（sleep）

論文「Language Models Need Sleep」の運用近似です。手動の /sleep と、コンテキスト圧縮の直前に走るフック（直近の実行から5分以内なら静かに終了）の2つの入口から、同じ6手順を踏みます。

1. 蓄積を走査（scan） 2. 看板へ反映 3. 記憶へ書く 4. ログを書く 5. 最終実行を記録 6. 設定を git に保存

モデルの使い分け（重さは難度で決める）

サブエージェントの既定モデルは、各定義ファイルの宣言（frontmatter）が唯一の既定です。呼び出し側で上書きするのは「不可逆・共有物の設計判断」「事実の正確さが致命的」「判断軸が言語化できていない」の3条件のときだけで、下げるのは自由。件数が多いことは昇格の理由になりません。下のバーは、起動可能な62体の割り当て比率です。

sonnet38体 — 実装・レビュー・テスト
haiku14体 — 探索・転送役（ワーカーの殻）
opus ほかopus 6体・GPT-5.6 系 4体

// Authority

Traffic Lights判断のルール — 自律の範囲

AIの暴走を防ぐための線引きです。信号機の色で「自ら決定してよい／確認のうえ実行／絶対に行わない」を区分します。判断に迷う場合は、必ず黄（確認）に倒します。

緑

GREEN · 無確認で実行可

自らの判断で実行し、完了後に1行で報告します。

  • ファイルの読み取り・検索
  • 看板・受け渡しフォルダの更新
  • 記憶の追加
  • 基本14体・現役スタックの助っ人AI
  • 外部ワーカーの単独起動

黄

YELLOW · 要確認

選択肢を2〜4個提示し、いったん停止して確認します。承認後は緑として実行。

  • スキル・エージェント・設定の編集
  • プロジェクト本体の変更・commit・push
  • 3体以上の多重起動・Workflow
  • 現役スタック外の助っ人AI

赤

RED · 絶対禁止

いかなる状況でも実行せず、依頼があっても理由を返して停止します。

  • 認証情報の送信・露出
  • 課金・資金移動
  • メインブランチの破壊的 Git 操作
  • ローカルで処理できるファイルの外部アップロード
  • public リポジトリへの push
自身の作業範囲のみ
共有・設定・プロジェクト
やり直せる可逆
緑そのまま実行し報告
黄選択肢を提示し確認
やり直せない不可逆
黄選択肢を提示し確認
赤実行しない

※「常に赤」の特例は、この表より先に判定されます。また「好きにやっていい」のような汎用的な励ましは、設定やスキルの自己改変の承認にはなりません。応答できない状況（就寝中など）も承認とは見なしません。

ルール自体を監査する（Jev）

書いたルールが曖昧でないかを、TypeSafe の Jev（System One）に判定させて確かめています。ルールを渡して操作ごとに緑・黄・赤を選ばせ、自分の解釈と突き合わせます。実行時の判断経路には入れず、監査だけに使います。

段階1 読解の確認
表で答えが決まる22問を先に解かせる（22/22 正解）。ここで読み違えないことを確かめてから次へ進む
段階2 曖昧さの発見
境界のケースを解かせ、ズレと確信度の低い問いを「ルールの穴」の候補にする
結果
ズレ 4→0、最低確信度 0.21→0.59。ルールに9項目を追加（例: public への push を赤に）

委任の階層（常に緑の基本14体）
